# Engineering decisions

## Keep progression rules independent of the platform

`GameEngine` handles inputs such as domain ratings, quest difficulty and evidence confidence. `GameSession` applies those rules to state transitions and records the corresponding ledger entries. Tests can exercise day settlement with controlled time and calendar inputs. Standard UI actions can still create IDs and timestamps. The determinism claim applies to scoring given fixed inputs.

This boundary makes business rules easy to test. It also means model validation matters at every entry point. A manual proof note is a self-reported result, and an imported reference can inform a completion without awarding progression on its own.

## Save state before showing rewards

`AppStore.mutate` copies the session, applies the change and asks `SessionRepository` to save the candidate. Only a successful save replaces the visible session. An injected failure checks that balances stay unchanged. An automatic backup error is surfaced separately because the database write may already be durable.

SwiftData stores immutable full-session revision envelopes. Each revision references its parents. A repository opened on an old head checks the current heads before writing. When multiple heads remain, the app preserves working versions and exposes them for review. This is an optimistic stale-write check. Concurrent writers can still produce branches, which is why preserving ancestry matters.

## Give automatic merging a narrow scope

`SafeSessionMerge` compares protected state and only unions independent additions to reviews, activity and the evidence inbox. Matching IDs must describe the same record. Scoring disagreement, conflicting edits and incomplete ancestry require review. Summing two balance changes would double-count some actions and cannot safely resolve differing histories.

Whole-state revisions keep validation and restore understandable. They also grow with both history and snapshot size. The repository fetches revision rows and caches previously validated payloads. Measure cold load, warm load, save, recovery and file growth before adding compaction. The source release makes no storage throughput or concurrency SLA.

## Keep portable recovery separate from the database

A portable JSON backup contains a format version and SHA-256 checksum over its payload. Restore validates sizes, references and numerical bounds before applying changes. Legacy records have a dedicated migration path. Corrupted revisions are preserved for inspection. Recovery can restore into a fresh local store while retaining the original for diagnosis.

File and platform-side operations have different failure boundaries from the database. An irreversible cleanup must report unfinished steps accurately. Read the purge implementation and its failure-injection checks together before changing cleanup order.

## Make optional services independent of the core

The backend uses separate credentials for authenticated app reads and evidence ingestion. The VS Code extension sends only opt-in activity summaries and opaque workspace identifiers. The planner validates structured responses, asks for explicit acceptance, and keeps a local fallback. Local data and rewards remain usable without a configured endpoint.

## Asset provenance

The app icon is first-party artwork generated by `scripts/generate_icon.swift` from simple geometric paths and colors. The generator uses Apple drawing APIs and requires no external images, fonts or design files. After regenerating, run `python3 -B scripts/strip_png_metadata.py App/Assets.xcassets/AppIcon.appiconset/*.png` to remove generated metadata. SwiftUI uses the OS system font and system symbols at runtime. Repository screenshots are captured from the real application running synthetic fixtures. They include no private workspace or desktop capture.
